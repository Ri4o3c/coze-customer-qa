# 项目完成后的学习顺序

先从用户能看到的输入输出开始，不必一上来背节点参数。

1. 读data/single_violation.json：确认客户、客服角色和要审查的行为。
2. 读knowledge/R02_敏感凭证.txt：明白“违规”依据是什么。
3. 读prompts/system.txt：模型负责理解语义、分类和给候选结论。
4. 读nodes/03_validate.py：代码负责字段与证据存在性校验，不能替代自然语言判断。
5. 看正常分流与人工复核分支：unknown不能当pass，违反规则也不一定需要再次判断是否违反。
6. 看nodes/07_batch_summary.py：为什么用ticket_id归并，以及为什么review_count不能与合规/违规数相加。
7. 运行tests/test_nodes.py：理解软件测试的范围，再做Coze实际模型评测。

可以用一句话讲清：检索提供规则，模型提出质检判断，代码检查结构与引用，选择器安排人工复核，批处理复用同一条链路。

面试时遇到“怎么证明准确”，展示具体输入、规则、客服原文和实际输出，再说测试范围。不要用“接口成功返回”或“33项代码测试通过”代替模型质量证据。
