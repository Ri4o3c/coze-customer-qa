## 看哪里

- 预览：单条主工作流的可视化画布，包含输入校验、规则知识库检索、规则完整性、模型分析、JSON/证据校验与结果输出。
- 文件目录：src/graphs/graph.py是单条流程；src/graphs/batch_graph.py是批量流程。批量复用单条Graph，并发2、上限50。
- config/customer_qa_single_llm_cfg.json：实际模型选择与提示词。当前生成配置为doubao-seed-2-0-pro-260215，以保存的配置文件为准。
- src/graphs/nodes：9个节点的实现。不要把本材料包nodes/01_prepare.py等Args接口代码直接覆盖这里。
- AGENTS.md：项目资源索引。它是生成项目的说明文件，不是本聊天的新指令。
- 运行记录：查看已完成的模型调用、输出与历史版本。旧版结果属于当时的代码版本，不能证明后续修改已完成回归。

## 单条输入

在预览页点“试运行”，设置开始节点record_json为String，粘贴data/single_normal.json内容。例如：

```json
{"ticket_id":"DEMO-001","messages":[{"role":"customer","text":"我的包裹三天没更新了。"},{"role":"agent","text":"您好，我帮您联系物流核实。"}]}
```

点击运行。正常完成后查看结束节点的result_json、report、needs_review。若界面采用整体参数JSON编辑器，则使用data/single_normal_start_params.json的外层包装格式。

模型调用失败应进入人工复核，不应得到“全通过”。这些小样例用于演示与回归，不代表生产准确率。

## 批量输入

批量模块的输入是records_json:String，值为data/batch_demo.json的数组文本。当前已验证的是开发态批量Graph执行，不是公开部署的产品入口。

当前预览只展示单条main_graph，不要把records_json硬塞进单条record_json。批量请在Coze项目终端运行：

```bash
PYTHONPATH=src python scripts/run_demo.py batch
```

它调用graphs.batch_graph.batch_main_graph，默认处理6条演示输入。自定义批次可参考该脚本修改records数据或直接调用batch_main_graph。批量没有独立画布预览入口，这是当前第一版的界面限制。

## 两套材料的边界

本包保留传统低代码画布材料，方便你理解每一步并将来迁回旧版画布。线上扣子编程项目是另一套使用Graph与状态类型的实现。两套都围绕同一业务目标，但不能混用输出Schema或测试数量。

- 本地44项测试：针对本材料包nodes目录与评分脚本。
- 线上模型演示：只针对平台当时保存版本的真实运行。
- 平台边界测试：34项通过，完整输入输出见线上项目源码verification/hardening_result.json。

线上最终输出目前checks是按R01/R02/R03键组织的Object，validation/semantic_review也是Object；传统节点材料输出checks为Array。若要对线上结果使用本包评分器，需先按规则ID转换成数组；原始输出应保留，不能篡改业务标签。
